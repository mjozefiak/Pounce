# ADR 0007: Rename Pounce to Lintel, identity included <!-- LEGACY-POUNCE -->

- Status: accepted (the owner decided on 2026-11-04)
- Date: 2026-11-04
- Plan: `.ai/runs/2026-11-04-lintel-rebrand.md`, PR #49
- Numbering: 0006 is taken by the speech-layer extraction on the meetings branch, so this is 0007.

## Context

The name Pounce was dropped for a new one, Lintel, with a new mark and a Verdigris accent. The identity that <!-- LEGACY-POUNCE -->
macOS and the user's data hang on is named after the old app: the bundle identifier, the Keychain services, the
Application Support folder, the `UserDefaults` domain and the signing certificate. `BACKWARD_COMPATIBILITY.md`
protects all of them, and the identifier cannot be changed after the first release without every user losing
their permission grants.

No release exists (no tags), so the only installation is the owner's Mac. That makes this the last moment at
which the identity can be renamed at the price of one re-grant on one machine.

## Decision

Rename everything, not only the visible name: the bundle identifier becomes `com.lintelapp.Lintel`, the Keychain
services `com.lintelapp.*`, the data folders `Lintel`, the SwiftPM modules `Lintel*`, the certificate "Lintel
Release". `PluginID`s, settings keys, item keys and database schemas stay, because renaming them gains nothing
and would need real migrations.

Existing data follows through three one-time steps that never delete anything they cannot prove is moved:

- `LegacyDataMigration` renames the folders before the new ones exist and copies the app's own `UserDefaults`
  values once.
- `MasterKeyStore` copies a master key from the old service name when the new item is missing. An old item that
  cannot be read is `failed`, never `missing`, so the only outcome that may reset a store is unchanged.
- Permissions belong to the bundle identifier and cannot be carried over; the system asks again.

The rename is generated by `.ai/scripts/rename-to-lintel.sh`, which protects the repository URL (the GitHub
repository keeps its name), the historical spec file name and every line marked `LEGACY-POUNCE`, and which can be
run again on any branch that was written against the old names (the meetings plugin).

## Consequences

- The owner re-grants Accessibility, Full Disk Access, the microphone and Launch at Login once.
- macOS may ask once for access to the old Keychain items; "Always Allow" ends it.
- A certificate named "Lintel Release" has to be created before the first tag
  (`docs/signing.md`); until then the release workflow fails on the designated requirement on purpose.
- The reverse-DNS prefix `com.lintelapp` assumes the owner controls `lintelapp.com`. The domain was not
  registered yet when this was written. It must be settled before the first release, because the identifier
  cannot change afterwards.
- Branches written against the old names conflict with this change; re-running the script resolves the mechanical
  part. Other source files may still need a manual merge.
