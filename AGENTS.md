# AGENTS.md

Instructions for coding agents (and humans) working in this repository.

## Project overview

Pounce is a fast, native macOS launcher with three features: app search, file search and clipboard history. It is a menu-bar agent app (`LSUIElement`) written in Swift 6 with AppKit (`NSPanel`) and SwiftUI, built with Swift Package Manager. Search uses its own in-memory filename index kept fresh with FSEvents (not Spotlight) and an fzf-style matcher with frecency ranking; clipboard history is stored encrypted (SQLCipher, key in the Keychain) and pastes into the previous app. Pounce is MIT-licensed and distributed as a DMG built by a tag-triggered GitHub Actions workflow, plus a landing page on GitHub Pages. Target: macOS 26+ on Apple silicon.

**Status: Phase 3 (file search, v0.3).** The MVP spec is `.ai/specs/2026-10-31-pounce-launcher-mvp.md` (Polish prose, English identifiers). Phase 0 delivered the Swift package, the `PounceKit` plugin contract, `PluginRegistry` and `PluginHost`, the menu bar shell, CI and the signed DMG release workflow. Phase 1 added the matching and ranking core, `ranking.sqlite`, the first plugin (`AppsPlugin`), the launcher panel, the global shortcut with the first-launch Shortcut step, and the Settings window. Phase 2 added `ClipboardPlugin` (encrypted history, ⌘⇧V list mode with preview, paste into the previous app, safety controls), list panel modes in the shell, per-command shortcut recorders and plugin onboarding steps. Phase 3 added `FilesPlugin` (its own filename index kept fresh with FSEvents, a saved snapshot, the Full Disk Access step before the first scan, file actions and the Files settings pane), plugin status lines above the results (`SearchStatus`), and the user-defined result order (`app.sectionOrder`). Everything marked **planned** below comes from a later phase of the spec and does not exist yet; when you create it, follow the layout here or update this file in the same PR.

## Architecture: features are compile-time plugins

Every feature (apps, files, clipboard, and anything added later) is an **internal, compile-time plugin** (spec decision Q9):

- It lives in **its own SwiftPM target** under `Sources/<Name>Plugin/` (`AppsPlugin`, `FilesPlugin`, `ClipboardPlugin`) with its own test target under `Tests/<Name>PluginTests/`.
- It conforms to the `PouncePlugin` protocol from the contracts-only target `PounceKit` (`PluginManifest`, `PluginContext`, `SearchSource`, `Candidate`, `MatchResult`, `ResultAction`, `PanelMode`, `PluginCommand`, `OnboardingStep`, `Permission`, plus the DI ports `KeychainClient`, `PasteboardClient`, `EventPoster`, `WorkspaceClient`, `UsageRecorder`, `PermissionsReader`, `SettingsStore`). Every contribution has an empty default in a protocol extension.
- It is **registered in exactly one place**: `Sources/PounceApp/PluginRegistry.swift` (`static let all: [any PouncePlugin.Type]`, today `[AppsPlugin.self, FilesPlugin.self, ClipboardPlugin.self]`). `PluginHost` in `PounceApp` owns the lifecycle (`activate()` / `deactivate()`, enable/disable, `failed` state, per-source time budget). Adding a feature = a new target, a `PounceApp` dependency on it, and one line in `PluginRegistry`.
- **Dependencies flow one way:** plugins → `PouncePersistence` / `PounceCore` → `PounceKit`. `PounceKit`, `PounceCore` and `PouncePersistence` never import a plugin; plugins never import each other or `PounceApp`. `PounceApp` is the only composition root and the only target that knows concrete plugins (and only in `PluginRegistry`). The SwiftPM graph enforces this.
- `PounceCore` is pure logic without I/O (`TextNormalizer`, `FuzzyMatcher`, `Ranker`); `PouncePersistence` is GRDB, the per-owner `DatabaseMigrator` factory, `UsageRepository` over `ranking.sqlite` and the atomic-write helper.
- Plugins share one process, so plugin code (outside tests) never traps: no `fatalError`, `try!` or force unwrap (risk R7). `activate()` and `search` report errors by throwing.
- There is **no runtime loading** of code (no bundles, dylibs, scripts or extension stores). Third-party or runtime-loaded plugins are out of MVP scope; the internal plugins above are in scope (Q9).

| Plugin contracts | `Sources/PounceKit/`, `CODE_REVIEW.md` (plugin rules), `BACKWARD_COMPATIBILITY.md` | Contracts only, no implementation. | Matching and ranking core | `Sources/PounceCore/` (`TextNormalizer`, `FuzzyMatcher`, `Ranker`), `Tests/PounceCoreTests/` | No I/O; the `Ranker` receives usage stats as an argument. Matching tiers: exact > prefix > word start/acronym > substring > fuzzy; frecency never promotes across tiers. No feature-specific logic in core. |
| App shell, panel, hotkeys, settings | `Sources/PounceApp/` | `@MainActor` for all UI (the target uses default `MainActor` isolation). `PluginRegistry`, `PluginHost` (lifecycle, `failed` state, per-source budget via `SourceRunner`), `AppCoordinator` (composition root), `StatusItemController`, `AppEnvironment` (data and caches roots, DI port implementations, `ranking.sqlite`), `SettingsKeys`, DEBUG-only `QA/QAOptions.swift`; `Search/SearchCoordinator` and `Search/SectionOrder` (sections follow `app.sectionOrder`, then `manifest.order`; the active plugins' `searchStatus` lines are shown above the results); `Panel/` (`LauncherPanel`, `PanelController`, `PanelModel`, `LauncherView`, `SearchField`, `IconCache`, `TextSize`); `Hotkeys/` (`HotkeyService`, `SymbolicHotkeys`, `HotkeyShortcut`, the KeyboardShortcuts registrar); `Settings/` (AppKit window with SwiftUI General and Features panes, `AppSettings`, Launch at Login, the Result Order list in Features); `Onboarding/` (first-launch Shortcut step, then the active plugins' `onboardingSteps`, each shown once). Plugins are registered in `PluginRegistry` and nowhere else; `SearchCoordinator` queries sources in a `TaskGroup` with a per-source budget (150 ms). Default hotkey ⌘Space, or ⌃⌥Space when Spotlight holds it, confirmed in a first-launch recorder step (Q10); a user-chosen shortcut always wins. Settings keys (`app.*`, `plugins.<id>.*`) are a protected contract. |
| App search plugin | `Sources/AppsPlugin/`, `Tests/AppsPluginTests/` | Directory scan is the source of truth; `NSMetadataQuery` only supplements. Dedupe by bundle ID. Icons load off the main thread (`IconCache` in the shell). Settings `plugins.apps.roots` and `plugins.apps.spotlight`; list cache `apps.json` in the plugin's caches directory. |
| File search plugin | `Sources/FilesPlugin/`, `Tests/FilesPluginTests/`, `docs/perf.md` | Filenames only, no content search. `RootPlanner` decides the roots from the settings and Full Disk Access (without it Desktop, Documents, Downloads and iCloud Drive are skipped unless added one at a time, so there are no TCC prompts); `IgnoreRules` (default exclusions `node_modules`, `.git`, `~/Library`, caches, `DerivedData`; user names, `*` patterns and paths); `BulkScanner` (`getattrlistbulk`, parallel on a GCD queue, never enters packages, other volumes or firmlinks; only a root may be a symbolic link, which is followed); `NameStore` (flat arrays, about 80 B per entry) owned by `actor FileIndex`, which publishes immutable copies so a search never waits for a scan; `FileSearch` (parallel top-N, byte prefilter, then `FuzzyMatcher`); `FileEventWatcher` + `RescanPlanner` (FSEvents, coalesced rescans, dropped events and `MustScanSubDirs` handled); `IndexSnapshot` (versioned LZFSE file written atomically to `Plugins/files/index.snapshot`, replayed from its FSEvents id on launch); `IndexController` runs all of it. The first scan waits for the `files.fullDiskAccess` onboarding step or "Start Indexing" in Settings. Item keys `files:<absolute path>`. Settings `plugins.files.*`; `plugins.files.qaHome` (DEBUG only) gives QA a fake home. TSan runs on `FilesPluginTests` in CI. |
| Clipboard plugin | `Sources/ClipboardPlugin/`, `Tests/ClipboardPluginTests/`, Data Model section of the spec, `docs/decisions/0002-pasteboard-reads.md` | Never log clipboard contents. Skip concealed/transient types and ignored apps (`CaptureFilter`). Only `errSecItemNotFound` may reset the database (`HistoryOpener` archives the old file); every other Keychain error disables history without deleting anything. Nothing from the clipboard is written to `ranking.sqlite`: the plugin never calls `PluginContext.usage`, its list mode ranks with `use_count`/`last_used_at` from `clipboard.sqlite`. `NSPasteboard` is read on the main actor (ADR 0002); classification, hashing and storage run in the background. `KeyStore` (master key in the login keychain, HKDF sub-keys), `ClipStore` (SQLCipher, FTS5, AES-GCM blobs > 1 MB), `PasteboardWatcher`, `RetentionJob` (30 days / 1000 entries), `PasteService` (layout-aware ⌘V, copy-only fallbacks), settings `plugins.clipboard.*`. Tests use a named pasteboard, an in-memory keychain and temporary directories. |
| Persistence and migrations | `Sources/PouncePersistence/`, `BACKWARD_COMPATIBILITY.md`, `docs/decisions/0001-sqlite.md` | `DatabaseFactory.openQueue` opens every database (encrypted with a `DatabaseKey` raw key, or plain) with its owner's migrator and mode 0600; `UsageRepository` owns `ranking.sqlite` (migration `v1-usage`). Two separate databases: `ranking.sqlite` (plain, at the Application Support root, owned by `PounceApp` and shared through `UsageRecorder`) and `clipboard.sqlite` (SQLCipher, in `Plugins/clipboard/`, private to `ClipboardPlugin`, with its own migrator). Plugin data lives in `Plugins/<id>/` (0700), files `0600`. GRDB `DatabaseMigrator`, additive migrations only. SQLCipher variant chosen in spike 0.4: GRDB 7.11.1 with SQLCipher.swift 4.20.0 (`docs/decisions/0001-sqlite.md`). |

## Validation

Validation gate, in order (also in `.ai/agentic.config.json`):

1. `swift build`
2. `swift test`
3. `swift format lint --strict -r Sources Tests`

Every PR that touches Swift code or the package manifest must pass the full gate; docs-only PRs say so in the PR body. CI (`.github/workflows/ci.yml`) runs the same commands plus the `PluginHost` and `FilesPlugin` tests under `--sanitize=thread`. On a developer Mac, run `swift package resolve --disable-keychain` once after cloning so SwiftPM downloads the SQLCipher binary without a Keychain lookup.
