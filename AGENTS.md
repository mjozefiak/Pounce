# AGENTS.md

Instructions for coding agents (and humans) working in this repository.

## Project overview

Lintel (called Pounce until 2026-11-04, see `BACKWARD_COMPATIBILITY.md` section 0) is a fast, native macOS launcher with four features: app search, file search, clipboard history and dictation, all on the Mac. It is a menu-bar agent app (`LSUIElement`, with an optional Dock icon, `app.showInDock`) written in Swift 6 with AppKit (`NSPanel`) and SwiftUI, built with Swift Package Manager. Search uses its own in-memory filename index kept fresh with FSEvents (not Spotlight) and an fzf-style matcher with frecency ranking; clipboard history is stored encrypted (SQLCipher, key in the Keychain) and pastes into the previous app. Lintel is MIT-licensed and distributed as a DMG built by a tag-triggered GitHub Actions workflow, plus a landing page on GitHub Pages. Target: macOS 26+ on Apple silicon. <!-- LEGACY-POUNCE -->

**Status: Phase 4 (v1.0 polish) plus the main window (ADR 0008, spec `2026-11-04-lintel-main-window`, Phases 0–6 done: the window is enabled for users).** The MVP spec is `.ai/specs/2026-10-31-pounce-launcher-mvp.md` (Polish prose, English identifiers). Phase 0 delivered the Swift package, the `LintelKit` plugin contract, `PluginRegistry` and `PluginHost`, the menu bar shell, CI and the signed DMG release workflow. Phase 1 added the matching and ranking core, `ranking.sqlite`, the first plugin (`AppsPlugin`), the launcher panel, the global shortcut with the first-launch Shortcut step, and the first Settings window (replaced by the main window's Settings mode in step 6.3). Phase 2 added `ClipboardPlugin` (encrypted history, ⌘⇧V list mode with preview, paste into the previous app, safety controls), list panel modes in the shell, per-command shortcut recorders and plugin onboarding steps. Phase 3 added `FilesPlugin` (its own filename index kept fresh with FSEvents, a saved snapshot, the Full Disk Access step before the first scan, file actions and the Files settings pane), plugin status lines above the results (`SearchStatus`), and the user-defined result order (`app.sectionOrder`). Phase 4 (v1.0, no new features) added Settings → Permissions and Advanced (Reset Ranking), the welcome screen that combines the Shortcut step with the enabled plugins' onboarding steps, the About window with the third-party notices, an accessibility audit of every screen, the landing page and the performance budgets in `docs/perf.md`. The main window (one window with Workspace and Settings modes, a sidebar, status banners, the Models pane and destructive confirmations as sheets) replaced the toolbar Settings window and opens from the Dock, ⌘, and the menu bar for every user. The meeting-notes spec (`.ai/specs/2026-11-03-meeting-notes.md`) adds `MeetingsPlugin` (off by default): Phase 1 delivers transcripts with speakers, the meeting library list mode and the meeting window; Phase 2 adds the notes (a built-in language model writes a summary, key points, decisions, tasks and open questions in the background, every point checked against the recording); the meeting prompt (Phase 3, off by default) is `MeetingDetector` and its parts (see the Meetings plugin row). Everything marked **planned** below comes from a later phase of the spec and does not exist yet; when you create it, follow the layout here or update this file in the same PR.

## Architecture: features are compile-time plugins

Every feature (apps, files, clipboard, and anything added later) is an **internal, compile-time plugin** (spec decision Q9):

- It lives in **its own SwiftPM target** under `Sources/<Name>Plugin/` (`AppsPlugin`, `FilesPlugin`, `ClipboardPlugin`, `DictationPlugin` and `MeetingsPlugin`) with its own test target under `Tests/<Name>PluginTests/`.
- It conforms to the `LintelPlugin` protocol from the contracts-only target `LintelKit` (`PluginManifest`, `PluginContext`, `SearchSource`, `Candidate`, `MatchResult`, `ResultAction`, `PanelMode`, `PluginCommand`, `OnboardingStep`, `Permission`, plus the DI ports `KeychainClient`, `PasteboardClient`, `EventPoster`, `WorkspaceClient`, `UsageRecorder`, `PermissionsReader`, `SettingsStore`). Every contribution has an empty default in a protocol extension.
- It is **registered in exactly one place**: `Sources/LintelApp/PluginRegistry.swift` (`static let all: [any LintelPlugin.Type]`, today `[AppsPlugin.self, FilesPlugin.self, ClipboardPlugin.self, DictationPlugin.self, MeetingsPlugin.self]`; `MeetingsPlugin` is registered since step 1.10, so the "Meetings" toggle is in Settings → Features, off by default). `PluginHost` in `LintelApp` owns the lifecycle (`activate()` / `deactivate()`, enable/disable, `failed` state, per-source time budget). Adding a feature = a new target, a `LintelApp` dependency on it, and one line in `PluginRegistry`.
- **Dependencies flow one way:** plugins → `LintelUI` / `LintelSpeech` / `LintelPersistence` / `LintelCore` → `LintelKit`. `LintelKit`, `LintelCore`, `LintelPersistence` and `LintelUI` never import a plugin (and `LintelUI` never imports `LintelApp`; it imports only `LintelKit`, `LintelCore`, SwiftUI and AppKit, checked by `LintelUITests/PackageGraphTests`); plugins never import each other or `LintelApp`. `LintelApp` is the only composition root and the only target that knows concrete plugins (and only in `PluginRegistry`). The SwiftPM graph enforces this.
- `LintelSpeech` (ADR 0006, extracted from `DictationPlugin` without a change of behaviour) is the shared speech layer: `AudioPorts` (`AudioInput`, `SpeechEngine`, `VoiceActivityDetector`, `SampleStore`), `MicrophoneCapture`, `ParakeetEngine` + `SileroVAD` + `LazyVAD`, `WhisperKitEngine` + `SwitchingEngine` + `RepetitionFilter`, `ModelCatalog` / `LLMModelCatalog`, `ModelManager` + `ModelDownloader`, and the llama.cpp runtime (`LLMRuntime` with the neutral `ChatMessage`, `LlamaRuntime(contextLength:)`, `generateResult` with the token-limit flag, `KeepWarmRuntime`). Everything a plugin uses is `public`. `ModelManagers.shared` hands out one `ModelManager` per directory (installs and deletes run one at a time). `SpeechEngineLease.shared` and `LLMLease.shared` own every engine/LLM load and unload: key `(model id, folder)` / `(model id, context length)` shared by a counter, one resident model, `ModelLeaseError.busy` for another key while a lease is active (an idle warm model is replaced at once), keep-warm from the last release, `interactive` before `background` in one queue, a running `background` generation cancelled between tokens and retried, and a `.spool` result when the background speech queue holds 60 s of audio; their tests run under TSan in CI. `DictationPlugin` goes through them (`KeepWarmRuntime` is a thin adapter over `LLMLease`). It depends on no repository target and on no plugin (only Foundation, AVFoundation, FluidAudio, WhisperKit and the `llama` XCFramework), and plugins may import it, never each other. Models live in `Application Support/Lintel/Models/{speech,llm}/` (`PluginContext.modelsDirectory`).
- `LintelUI` (ADR 0008, decision 8) holds what plugin settings panes share with the shell, SwiftUI and AppKit without I/O: `LintelBrand` and `BrandPalette` (the brand tokens, `status.ok` / `status.attention` / `status.error` included, and the prototype's warm neutrals `windowBackground`, `sidebarBackground`, `card`, `secondaryText`, `hairline`, `fill` and `windowSelectionTint`, which the main window, Settings, the welcome screen and the plugin panes use instead of the system greys; `WarmNeutralSourceScanTests` rejects `.secondary`/`.tertiary`/`.quaternary`, `separatorColor`, `controlBackgroundColor`, `windowBackgroundColor`, the label and system fills and `Divider()` there; the launcher panel keeps its glass), `LintelDivider` (the hairline), `TextSize` with the environment value `lintelTextSize` and the modifier `.lintelTextSize(_:)` (sets it and `.dynamicTypeSize`; `LintelTextSizeScope` reads an observed size while it renders; `AppTextSize.current`, set by `AppCoordinator`, gives plugin-owned windows `app.textSize`), `SettingsPane` (Basics, Advanced `DisclosureGroup`, Data; no banner), `SettingsFooter`, `ConfirmSheet` (Cancel is the default button) with `DestructiveConfirmation` + `.destructiveConfirmation(...)` (always the sheet; `detail` is the "This can't be undone." text; used by every Clear, Erase and Reset in the panes, step 3.4), `MenuPicker` (a settings-row menu picker whose value follows the text size, Dictation and Meetings), `ModelChoiceRow` (the main window's one-line model summary in the Dictation and Meetings panes, "Parakeet Ultra · not installed · Get it in Models", which calls `PluginContext.openModels`, step 3.3; the plugins' model cards stay only for the welcome screen's setup steps), `ThingsToDo` (the plugin banners' "N things to do" title, counting the denied readable permissions the shell adds to the detail), `AppActivationObserver` (calls a plugin back when Lintel becomes the active app, so Files and Clipboard re-check permissions there and their `settingsStatus` getters only read), `SettingsLayout` (the pane's shared widths and spacing), and the welcome screen's single column (`WelcomeLayout`, `WelcomeStepLayout` for every page, and for a plugin step's controls `WelcomeStepColumn`, `WelcomeStepItem`, `WelcomeStepDone`, `WelcomeStepNote`; `WelcomePluginPagesScanTests` keeps the four plugin steps on it). Every host (`MainWindowController`, `MeetingWindowController`, the welcome and About windows) applies `lintelTextSize`; views read sizes only through it. In-tree, not a protected contract.
- `LintelCore` is pure logic without I/O (`TextNormalizer`, `FuzzyMatcher`, `Ranker`); `LintelPersistence` is GRDB, the per-owner `DatabaseMigrator` factory, `UsageRepository` over `ranking.sqlite`, the atomic-write helper, and the shared key logic for encrypted plugin stores: `MasterKeyStore(service:)` (Keychain master key, HKDF sub-keys) and `EncryptedDatabaseOpener` (the one reset policy: only `errSecItemNotFound` archives and resets, any other Keychain error leaves every file alone).
- Plugins share one process, so plugin code (outside tests) never traps: no `fatalError`, `try!` or force unwrap (risk R7). `activate()` and `search` report errors by throwing.
- There is **no runtime loading** of code (no bundles, dylibs, scripts or extension stores). Third-party or runtime-loaded plugins are out of MVP scope; the internal plugins above are in scope (Q9).

## Validation

Validation gate, in order (also in `.ai/agentic.config.json`):

1. `swift build`
2. `swift test`
3. `swift format lint --strict -r Sources Tests`

Every PR that touches Swift code or the package manifest must pass the full gate; docs-only PRs say so in the PR body. CI (`.github/workflows/ci.yml`) runs the same commands plus the `PluginHost` and `FilesPlugin` tests under `--sanitize=thread`. On a developer Mac, run `swift package resolve --disable-keychain` once after cloning so SwiftPM downloads the SQLCipher binary without a Keychain lookup.
