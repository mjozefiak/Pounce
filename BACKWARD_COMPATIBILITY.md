# Backward compatibility

What Lintel treats as a **protected contract surface**, what counts as a breaking change to each, and the path a change must take. Review skills check every PR against this file; implementation skills warn when a change does not comply.

Lintel has no public network API and no third-party plugin ecosystem. Its contracts are the internal plugin contract in `LintelKit` (every plugin target compiles against it), the data it keeps on the user's disk, the user's settings, and the code-signing identity that macOS uses to remember the user's permission grants. All surfaces below are **planned** (they arrive with the MVP phases in `.ai/specs/2026-10-31-pounce-launcher-mvp.md`); the rules apply from the moment each one first ships. The spec's risks R4 (formats, keys and paths are the hard-to-reverse contracts, fixed before v0.1) and R8 (`LintelKit` changes are additive only) are the source of the rules in sections 1 and 2.

Any PR that changes a surface below is `risk-high` (see `SDLC.md`) and states in its body which surface it touches and which path it followed.

## 1. Plugin contract (`LintelKit`)

**Surface:** the contracts-only target `LintelKit` that every plugin compiles against: `LintelPlugin` and its contributions (`searchSources`, `commands`, `panelModes`, `onboardingSteps`, `requiredPermissions`, `settingsPane()`, `activate()`, `deactivate()`, `eraseData()`), `PluginManifest`, `PluginID`, `PluginContext`, `SearchSource`, `Candidate`, `MatchResult`, `NormalizedQuery`, `SourceID`, `ItemKey`, `ResultAction`, `ActionContext`, `PanelMode`, `PluginCommand`, `OnboardingStep`, `Permission`, and the DI ports (`KeychainClient`, `PasteboardClient`, `EventPoster`, `WorkspaceClient`, `UsageRecorder`, `PermissionsReader`), and since v0.3 the `searchStatus` contribution with `SearchStatus` and `SearchStatusAction` (default: no status), and since the dictation contract `Permission.microphone`, `PluginCommand.onKeyEvent` with `KeyPhase` (default `nil`: the shortcut calls `run`), `PluginContext.claimEscapeKey` with `EscapeKeyClaim` (default: an inactive claim) and `PasteboardRepresentation.transientMarkerType` / `markerTypes` (the shared set of pasteboard marker types, which a release must never shrink), `PasteboardClient.itemTypes()` (default: the union as one item) and `PluginContext.openSettings` (default: does nothing). With app suggestions (`.ai/specs/2026-11-01-app-suggestions.md`): the `suggestionSources` contribution with `SuggestionSource` (default: no sources; `actions(for:)` defaults to none), the optional `Candidate.badge` (`String?`, init default `nil`) and three `WorkspaceClient` requirements with defaults: `applicationActivations()` (never yields), `runningApplicationBundleIDs` (empty) and `secondsSinceLastUserInput` (`nil`). They are protocol requirements, not extension-only methods, so calls through `any WorkspaceClient` reach the shell's implementation. `Candidate`'s `Hashable` is synthesised, so `badge` takes part in `==` and `hash`: the same item with and without a badge are two different candidates; the shell identifies rows by `ResultItem.id` (section plus item key), not by `==`. With the meeting notes spec (`.ai/specs/2026-11-03-meeting-notes.md`): `PluginContext.modelsDirectory` (`URL`, `Application Support/Lintel/Models/`; the initializer parameter `modelsDirectory: URL? = nil` defaults to `storageDirectory/Models`) and `Permission.systemAudioRecording` (its state cannot be read, so `PermissionsReader` reports `.notDetermined`). With the meetings settings (step 1.9): the `permissionAccessory(for:)` contribution (a requirement with a default of `nil`; Settings → Permissions shows the returned view under the permission's row for each enabled plugin that needs it) and the setting `plugins.meetings.diarizationModelFolder` (`String?`, a folder chosen by hand for the diarization model). Also the `PluginID` values (`apps`, `files`, `clipboard`) and the `<plugin id>:<key>` item-key format, because both are persisted.

The plugins are all in-tree and compiled together, so a break shows up as a compile error, not a runtime failure. The goal of this contract is to keep plugins independent and cheap to add (a new plugin = a new target and one line in `PluginRegistry`, with no change to `LintelKit` or `LintelCore` beyond additive ones), not to support external binaries.

**Breaking:** removing or renaming a requirement or type; changing a signature, `async`/`throws` effects, isolation (`@MainActor`, `Sendable`) or semantics (for example the ordering of match tiers, what `limit` means, or which action is first/second in `actions(for:)`); adding a protocol requirement or contribution without a default implementation; changing an existing `PluginID` or the item-key format.

**Required path:**

- Changes are **additive only** (R8): new contributions and requirements get a default in a protocol extension, new optional fields, new types.
- `PluginID` values and the `<plugin id>:<key>` format **never change after v0.1** (R4, R8): they appear in `ranking.sqlite`, in `Plugins/<id>/` paths and in `plugins.<id>.*` settings keys. Changing one is a **blocker**.
- A non-additive change is an exception to the spec, not a routine path. It needs an owner-approved amendment to the spec and an ADR in `docs/decisions/` (planned), and it must update **every** in-tree plugin and its tests in the same PR, so `main` never holds a plugin that does not conform.

## 2. On-disk data and migrations

Location: `~/Library/Application Support/Lintel/`. All files are `0600`; each plugin directory `Plugins/<id>/` is `0700`. Only `ranking.sqlite` and the shared model folder `Models/` live at the root; plugin data lives under `Plugins/<id>/`. The two databases are separate on purpose: a clipboard key problem must never touch ranking, and nothing from the clipboard (item ids, clipboard-mode query prefixes) is ever written to the unencrypted `ranking.sqlite`.

| Store | Owner | Format | Protected because |
|---|---|---|---|
| `ranking.sqlite` | `LintelApp`, shared with plugins through `UsageRecorder`; migrator in `LintelPersistence` | Plain SQLite (`usage_stat`, `query_association`), keys `<plugin id>:<key>` | Ranking is learnt over weeks; losing it is a visible regression. |
| `Plugins/clipboard/clipboard.sqlite` + `Plugins/clipboard/blobs/` | `ClipboardPlugin` only, with its own migrator | SQLCipher database (`clip_item`, `clip_representation`, `clip_fts`) + AES-GCM encrypted blob files with random UUID names | It is the user's history and cannot be rebuilt. |
| `Plugins/dictation/dictation.sqlite` | `DictationPlugin` only, with its own migrator (`v1-history`) | SQLCipher database (`dictation_entry`, `dictation_fts`); Keychain item `service = com.lintelapp.dictation`, `account = master-key`, same key scheme as the clipboard (`MasterKeyStore`) | It is the user's dictation history and cannot be rebuilt. |
| `Plugins/meetings/meetings.sqlite` (+ `Plugins/meetings/Spool/<meeting uuid>/`, temporary) | `MeetingsPlugin` only, with its own migrator (`v1-meetings`; registered since spec step 1.10) | SQLCipher database (`meeting`, `meeting_speaker`, `meeting_segment`, `meeting_fts`, `meeting_notes_fts`, all `notes_*` columns, and the recovery columns `resume_attempts` and `audio_gap`, from the first migration, which is still unreleased and so was extended in place); Keychain item `service = com.lintelapp.meetings`, `account = master-key`, same key scheme as the clipboard (`MasterKeyStore`), HKDF-SHA256 `info = sqlcipher` for the database and `info = spool` for the audio spool (each spool file gets its own sub-key, `info = spool/<lower-case uuid>/<track>/<salt hex>` with a random 16-byte salt stored in the file header, from step 1.3). The two full-text indexes read their text through the views `meeting_segment_indexed` and `meeting_notes_indexed`, which fold `ł`, `đ` and `ø` (SQLite's `remove_diacritics 2` leaves them alone), so searches fold the same letters. | It is the user's meeting transcripts and notes and cannot be rebuilt. The spool is not a promised format (it only lives until a meeting is processed, or `orphanAudioDays`), but its folder path and the delete rule are protected. |
| `Plugins/files/index.snapshot` | `FilesPlugin` | Since v0.3: the magic `PNCEIDX\0`, a little-endian `UInt32` schema version (1), then an LZFSE-compressed body (complete flag, last FSEvents id, plan fingerprint, roots with their FSEvents device UUID, then every node as parent, flags, mtime, raw name and folded name). Written atomically (temp file + `rename`, mode 0600) | Rebuildable by rescanning, so only the "never error" rule is protected. |
| `Models/speech/<package-id>/`, `Models/llm/<package-id>/` (and `<id>.partial` beside them) | `LintelSpeech`'s `ModelManager`, one instance per folder; used by every plugin that needs a model | Downloaded speech, voice activity and diarization models and GGUF files, pinned by revision and SHA-256. Since the meeting notes spec they replace `Plugins/dictation/Models/` and `Plugins/dictation/llm/`, moved once and atomically at launch (`ModelsMigration`, before plugins activate; if both source and target are non-empty nothing is merged or deleted). | Rebuildable by downloading again, so only the path and the migration are protected. Erase Data of a plugin does not remove them; only "Remove model" does, and only when no lease holds the model. |
| `Plugins/<id>/` paths | Each plugin | Directory layout | Part of R4: existing installs look for their data there. |
| `Plugins/apps/activity.json` | `AppsPlugin` only (app suggestions) | Since app suggestions: JSON `{"version": 1, "seededAt": String?, "apps": {<bundle id>: {"frecency": Double, "lastUsedAt": Double (Unix s), "useCount": Int}}}`, written atomically through `AtomicFile` (0600); entries unused for 90 days are pruned | Learnt over weeks, but rebuildable, so only the reset rules are protected: a file that does not decode (no integer `version`, or `version` 1 without its fields) is moved to one `activity.json.corrupt` (replacing the previous copy) and the store starts empty; a newer `version` makes the store read-only (no tracking, seed, writes or clearing, suggestions off) and leaves the file untouched. `seededAt` is an ISO 8601 date, `"skipped"` (Spotlight off) or `"cleared"` (cleared before the seed); missing means the Spotlight seed has not run. |
| `~/Library/Caches/Lintel/Plugins/apps/apps.json` and `~/Library/Caches/Lintel/icons/` | `AppsPlugin` (`apps.json`); the shell's `IconCache` (`icons/`, shared by every plugin's rows) | Cache | Not protected; may change freely. "Erase Data" removes a plugin's `Caches/Lintel/Plugins/<id>/`. |

**Breaking:** dropping or renaming a table or column; changing a column's meaning or type; any migration that deletes or rewrites user rows; moving a store or renaming a `Plugins/<id>/` path; changing the encryption scheme, the key derivation (HKDF-SHA256 from the master key with `info` = `sqlcipher` for the database, `blob` for blob files, `content-hash` for the `content_hash` HMAC) or the Keychain item (file-based login keychain, `kSecClassGenericPassword`, `service = com.lintelapp.clipboard`) in a way an existing install cannot open or deduplicate against; changing the snapshot format without bumping `schema_version`.

**Required path:**

- Databases change only through GRDB `DatabaseMigrator` migrations (one migrator per database owner) that are **additive** (new tables, columns with defaults, indexes). Existing migrations are never edited once released.
- Every migration ships with a test that opens a database at the previous released schema, with data, and migrates it.
- A destructive change (rare) needs a staged path across releases: add the new structure and backfill, ship, then remove the old one in a later release; plus a rollback note in the PR body.
- A crypto or key change must open existing databases with the old scheme and re-encrypt, never drop. The only permitted reset is the one in the spec: key definitively missing (`errSecItemNotFound`) with an existing database → archive to `clipboard.sqlite.unreadable-<date>`, keep it 30 days. The same rule applies to `dictation.sqlite` (`dictation.sqlite.unreadable-<date>`); any other Keychain error turns the history off and deletes nothing. And to `meetings.sqlite` (`meetings.sqlite.unreadable-<date>`, kept 30 days by `EncryptedDatabaseOpener`): any other Keychain error disables the library and recording and deletes nothing.
- `index.snapshot`: bump `schema_version` on any format change; an unknown or older version, a different FSEvents device UUID or `complete = false` must trigger a full rescan, never an error or crash.
- Downgrades are not supported, but a newer database must not be corrupted by an older build: an older build that sees a newer schema disables the feature with a message instead of migrating.
- Since v1.0, Settings → Advanced → Reset Ranking deletes every row of `usage_stat` and `query_association` (`UsageRepository.removeAllUsage()`), after the user confirms. Like Erase Data, it is an explicit user action, not a migration; the schema is unchanged.

## 3. User settings keys (`UserDefaults`)

**Surface:** every `UserDefaults` key and its value type and meaning, in the two namespaces from the spec: `app.*` (main shortcut, `app.hotkey.userDefined`, launch at login, text size, section order) and `plugins.<id>.*` (`plugins.<id>.enabled` and each plugin's settings: file index roots and exclusions, retention, ignored apps, recording paused), plus the shortcuts stored by KeyboardShortcuts and any key added later.

Keys in use since v0.1 (declared in `Sources/LintelApp/SettingsKeys.swift` and in each plugin): `app.hotkey.userDefined` (Bool), `app.hotkey.commandDefaultsApplied` ([String] of command ids whose default shortcut was applied once), `app.onboarding.shortcutCompleted` (Bool), `app.textSize` (`s`/`m`/`l`/`xl`), `app.panelLevel` (`floating`/`statusBar`, the spike 1.2 fallback), `plugins.<id>.enabled` (Bool), `plugins.apps.roots` ([String] or String), `plugins.apps.spotlight` (Bool); KeyboardShortcuts keys `KeyboardShortcuts_mainHotkey` and `KeyboardShortcuts_command_<command id with dots as underscores>`.

Keys added in v0.2 (Phase 2, clipboard): `app.onboarding.completedSteps` ([String] of plugin `OnboardingStep.id`s finished or skipped), `plugins.clipboard.paused` (Bool), `plugins.clipboard.retentionDays` (Int, default 30), `plugins.clipboard.maximumEntries` (Int, default 1000), `plugins.clipboard.ignoredApps` ([String] of bundle identifiers; missing means the default list), `plugins.clipboard.historyResetNotice` (Bool); KeyboardShortcuts key `KeyboardShortcuts_command_clipboard_history` (default ⌘⇧V). `plugins.clipboard.qaSeed` exists only in DEBUG builds and is not a contract.

Keys added in v0.3 (Phase 3, file search): `app.sectionOrder` ([String] of plugin ids, first section first; empty or missing means `manifest.order`; unknown ids are ignored), `plugins.files.roots` ([String] or String, absolute or `~/…`; missing or empty means the home folder and `/Applications`), `plugins.files.exclusions` ([String] of names, `*` patterns and `/…` or `~/…` paths, on top of the default exclusions), `plugins.files.protectedFolders` ([String] of `desktop`, `documents`, `downloads`, `icloud` added one at a time without Full Disk Access), `plugins.files.icloud` (Bool, default true: with Full Disk Access, iCloud Drive is indexed), `plugins.files.includeHidden` (Bool, default false), `plugins.files.setupCompleted` (Bool, default false: the first scan waits for it), `plugins.files.accessNoticeDismissed` (Bool, default false). `plugins.files.qaHome` exists only in DEBUG builds and is not a contract.

Keys added with app suggestions (`.ai/specs/2026-11-01-app-suggestions.md`, Phase 1): `plugins.apps.suggestions.enabled` (Bool, default `true`: learn which apps are kept in front and suggest them in the empty panel) and `plugins.apps.suggestions.hidden` ([String] of bundle identifiers hidden from suggestions; missing means none). The default `true` collects more data than before; the owner approved it as required below in [this comment on PR #10](https://github.com/mjozefiak/Pounce/pull/10#issuecomment-6576047488). `plugins.apps.qaActivity` and `plugins.apps.qaLiveActivity` exist only in DEBUG builds and are not a contract.

v1.0 (Phase 4) adds no keys. The welcome screen reads and writes the existing `app.onboarding.shortcutCompleted` (covers the welcome and shortcut pages; set when the shortcut page is finished or skipped, or the window is closed) and `app.onboarding.completedSteps` (the plugin steps), with the same meaning as before, so an install that finished onboarding never sees the welcome screen again.

**Breaking:** renaming or removing a key; moving a key to another namespace; changing its type or encoding; changing the meaning of a stored value; changing a default in a way that changes behaviour for users who never touched the setting (for example ignoring fewer apps by default, or capturing more types).

**Required path:**

- Declare keys in one place per target (constants, not string literals at call sites) so renames are visible in review.
- To rename or re-encode: read the old key, write the new one, and delete the old one in a one-time migration on launch; keep the migration for at least one minor release; test it.
- A default that weakens privacy (captures more, retains longer, ignores fewer apps) needs explicit owner approval in the PR.

Keys added with dictation (Phase 1, voice dictation; `plugins.dictation.*` is a protected namespace from the release that ships it): `plugins.dictation.speechModel` (String, default `parakeet-ultra`), `plugins.dictation.speechLanguage` (`pl`/`en`, default `pl`), `plugins.dictation.speechModelFolder` (String path, missing means the downloaded model), `plugins.dictation.inputDevice` (String UID, missing means the system input), `plugins.dictation.keepWarmMinutes` (Int, default 10), `plugins.dictation.restoreClipboard` (Bool, default true); KeyboardShortcuts key `KeyboardShortcuts_command_dictation_record` (default ⌃⌥D). Keys added with dictation formatting (Phase 2): `plugins.dictation.mode` (`raw`/`cleanup`, default `raw`), `plugins.dictation.llmEndpoint` (String URL, loopback only; a stored value that is not loopback is ignored), `plugins.dictation.llmModel` (String); command id `dictation.pasteLastRaw` (no default shortcut; its KeyboardShortcuts key is `KeyboardShortcuts_command_dictation_pasteLastRaw`). `CleanupPrompt.version` is a user-visible behaviour: a change bumps it and goes into the release notes. Keys added with the dictation history (Phase 3): `plugins.dictation.historyEnabled` (Bool, default true), `plugins.dictation.retentionDays` (Int, default 30), `plugins.dictation.maximumEntries` (Int, default 500); command id `dictation.history` (panel mode `dictation.history`, no default shortcut). Keys added with the built-in formatting model (Phase 4, ADR 0005): `plugins.dictation.llmSource` (`server`/`builtIn`, default `server`), `plugins.dictation.builtInLLMModel` (String, an `LLMModelCatalog` id; a stored id that is no longer in the catalog, or whose model does not fit this Mac's memory, means the default model). Downloaded models live in `Models/llm/<id>/` (before the meeting notes spec: `Plugins/dictation/llm/<id>/`) and are shared with other features, so Erase Data does not remove them.

Keys added with meeting notes (`.ai/specs/2026-11-03-meeting-notes.md`, step 1.2; `plugins.meetings.*` is a protected namespace from the release that ships the plugin, declared in `Sources/MeetingsPlugin/MeetingsSettings.swift`): `plugins.meetings.enabled` (Bool, default false, owned by the host), `plugins.meetings.speechModel` (String, default `parakeet-ultra`), `plugins.meetings.speechLanguage` (`pl`/`en`, default `pl`), `plugins.meetings.speechModelFolder` (String path, missing means the downloaded model), `plugins.meetings.inputDevice` (String UID, missing means the system input), `plugins.meetings.voiceProcessing` (Bool, default false), `plugins.meetings.diarization` (Bool, default true), `plugins.meetings.consentReminder` (Bool, default true), `plugins.meetings.notesEnabled` (Bool, default false, written only after an explicit choice), `plugins.meetings.builtInLLMModel` (String, an `LLMModelCatalog` id; a stored id that is no longer in the catalog, or whose model does not fit this Mac's memory, means the default model), `plugins.meetings.notesChunkTokens` (Int, default 3000), `plugins.meetings.notesReduceInputTokens` (Int, default 4500), `plugins.meetings.suggestMeetings` (Bool, default false), `plugins.meetings.suggestMutedBundleIDs` and `plugins.meetings.suggestExtraBundleIDs` ([String] of bundle identifiers, default empty), `plugins.meetings.retentionDays` (Int, default 90; the Settings choices are 7 / 30 / 90 / 180 / 365 / 0 for unlimited) and `plugins.meetings.orphanAudioDays` (Int, default 7: how long the spool of an interrupted meeting is kept). The 90-day default retention is a privacy-relevant default the owner approved in advance in the spec (Q12). Added with the record command (step 1.10): command ids `meetings.record` (default shortcut ⌃⌥M, in the menu bar menu) and `meetings.library` (a list mode, no default shortcut; it arrives with step 1.11), and the KeyboardShortcuts key `KeyboardShortcuts_command_meetings_record` (section 5). The command ids are persisted by KeyboardShortcuts and never change. Meeting suggestions (Phase 3, `.ai/specs/2026-11-03-meeting-notes.md`): `plugins.meetings.suggestMeetings` (Bool, default false; the detector listens to Core Audio only while it is true and the plugin is active, so turning it on is an opt-in to learning which app uses the microphone), `plugins.meetings.suggestMutedBundleIDs` (`[String]`, bundle IDs the user answered with "Nie pytaj dla tej aplikacji"; removed in Settings → Meetings; an ID is never added by anything else) and `plugins.meetings.suggestExtraBundleIDs` (`[String]`, apps the user added, for example a browser; at most 50, each a reverse-DNS identifier). The only other persisted trace is `meeting.source_bundle_id` (section 2), written only for a meeting the user started with the "Nagrywaj" button of a suggestion.

## 4. Code-signing identity, bundle identity and TCC grants

macOS ties Accessibility, Full Disk Access and Keychain access to the app's **designated requirement** (bundle identifier + signing certificate). If it changes, every user silently loses those grants on update and the clipboard key becomes unreachable.

**Surface:** bundle identifier `com.lintelapp.Lintel`; the stable self-signed "Lintel Release" certificate (stored as `SIGNING_P12` / `SIGNING_P12_PASSWORD` repo secrets); the designated requirement it produces; the Keychain item and its default ACL (trusts the app that created it); `LSUIElement`; entitlements; the DMG/app name users install.

The `com.apple.security.device.audio-input` entitlement (dictation) changes the signed entitlements but not the designated requirement; the release PR shows `codesign -dr -` unchanged and confirms by hand that Accessibility, Full Disk Access and Keychain survive an update.

**Breaking:** changing the bundle identifier; re-issuing or replacing the signing certificate; switching to ad-hoc signing; changing the code-signing requirement or entitlements in a way that alters the designated requirement; renaming the app bundle.

**Required path:**

- Release builds must produce an identical designated requirement across versions: verify with `codesign -dr -` on the new build against the previous release and include the output in the release PR.
- Moving to a Developer ID certificate (or any new certificate) is a one-time, deliberate break: it needs an ADR, release notes telling users to re-grant Accessibility / Full Disk Access, and a Keychain-access migration plan so clipboard history is not lost.
- Manually verify on each release that an in-place update keeps Accessibility and Keychain access (spec step 2.5).

## 5. Keyboard shortcuts and user-visible behaviour

Not a hard contract, but changes need a release note:

- **Default hotkeys** (spec Q6, Q10): ⌘Space opens the launcher, or ⌃⌥Space when Spotlight holds ⌘Space (⌥⌘Space is never used: it opens the Finder search window); ⌘⇧V opens clipboard history. The first launch shows a shortcut recorder prefilled with the default.
- **Meetings** (step 1.10): ⌃⌥M starts and ends a meeting recording (`meetings.record`, changeable in Settings → Meetings; only registered while the plugin is on). It must not collide with any other default: `DefaultShortcutTests` enumerates the shell's and every registered plugin's defaults (⌘Space / ⌃⌥Space, ⇧⌘V, ⌃⌥D, ⌃⌥M) and fails on a duplicate. The recording HUD stays visible in screen sharing, the "Poinformuj uczestników, że nagrywasz" reminder (`plugins.meetings.consentReminder`) is on by default, and `NSMicrophoneUsageDescription` says that meeting audio is stored encrypted until the transcript is ready; weakening any of these needs a release note.
- **Meeting notes** (`.ai/specs/2026-11-03-meeting-notes.md`, Phase 2): `NotesPrompt.version` is a user-visible behaviour like `CleanupPrompt.version`: the prompt decides what the notes contain, so any change to it (the wording, the point kinds, the language rules) bumps the version, regenerates the golden `notes-prompt-v1.txt` as a new file and goes into the release notes; notes already written keep the version that wrote them in `notes_prompt_version` and are never rewritten by an update. The `meeting.notes_*` columns have fixed meaning: `notes_status` is one of `none`, `running`, `ok`, `partial`, `failed`, `stale` (a new value needs a release note and a default in every reader); `running` is only ever set by a live job and is turned into `failed` when the library opens after a crash; `notes_markdown` is composed by code from verified points and is replaced only by a finished run (a failed or cancelled run keeps the earlier text); `stale` is set only by a speaker rename (or "To ja") when text exists or the first generation is `running`, and a finishing job keeps it (it stores its text as `stale`); `notes_model` is an `LLMModelCatalog` id, `notes_dropped_count` the points left out for lack of a quote in the recording, `notes_generated_at` a Unix time. Automatic notes (`plugins.meetings.notesEnabled`) stay off until the user turns them on, and a weaker default (on, or a model downloaded without a click) needs owner approval.
- **Meeting suggestions** (Phase 3): off by default and never starts a recording by itself. The suggestion HUD has clickable buttons only and claims no global key (no Return, no Escape, no key monitor), and it is hidden from screen sharing (`sharingType = .none`), unlike the recording HUD. Making them default on, adding a global key, or letting a suggestion start or stop a recording without a click needs a release note and the owner's approval.
- **A user-chosen shortcut always wins** (`app.hotkey.userDefined`): no automatic switch (⌃⌥Space → ⌘Space) and no new default may override a shortcut the user has recorded.
- **Result actions** (spec keyboard table): Return (first action; paste in clipboard mode), ⌘Return (second action), ⌘C / ⌘⇧C (copy path / file), ⌃X (delete a clipboard entry), ⌘1–⌘5 (clipboard type filter; in the empty search panel, since app suggestions, the n-th suggested app), ⌃X on a suggested app (Hide from Suggestions). ⌘⌫ stays the standard text-editing shortcut in the search field.
- **Paste into the previous app** in clipboard mode, falling back to copy-only without Accessibility or under Secure Event Input.
- **First launch** (v1.0): one welcome screen (welcome, shortcut, then each enabled plugin's steps, each skippable) replaces the separate shortcut window. **About Lintel** opens Lintel's own window with the third-party notices instead of the standard panel.

## Not protected

Internal types outside `LintelKit`, `LintelCore` internals, view layout, caches under `~/Library/Caches/Lintel/`, log messages, build scripts' internals and CI workflow structure may change freely, as long as the validation gate stays green.
