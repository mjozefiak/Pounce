# Execution plan: Phase 4 v1.0 polish (Pounce MVP)

Source doc: .ai/specs/2026-10-31-pounce-launcher-mvp.md
Branch: feat/v1-polish (base: feat/files-plugin, stacked on #7, which is stacked on #6, #4 and #3)

## Goal

Ship Phase 4 of the MVP spec (v1.0, steps 4.1–4.5) without new features: the Permissions and Advanced
Settings panes, a welcome screen that combines the enabled plugins' onboarding steps, an accessibility
audit of the whole app with every code-level finding fixed, an About window with the third-party
notices, the landing page on GitHub Pages with its workflow, an updated README, and the performance
budgets measured in `docs/perf.md`.

## Scope

- **4.1 Settings → Permissions:** one row per permission in the union of `requiredPermissions` of the
  enabled plugins, with the plugins that need it, its state (symbol and text, never colour alone), a
  deep link into System Settings and "Check Again"; refreshed when Pounce becomes active.
  **Settings → Advanced:** "Reset Ranking…" with a confirmation; clears `ranking.sqlite`
  (`UsageRepository.removeAll()`, a `PouncePersistence` addition; `PounceKit` untouched).
- **4.2 Welcome screen:** one window with a step list (Welcome, Shortcut, then the enabled plugins'
  `onboardingSteps` in plugin order), Back / Skip / Continue, each step skippable. Shown on first
  launch; after an update only the steps not in `app.onboarding.completedSteps` appear. Replaces the
  one-step-at-a-time window of Phases 1–3.
- **About window** (menu bar → About Pounce): version, licence, links and the bundled
  `THIRD_PARTY_NOTICES.txt`, replacing the standard About panel.
- **4.3 Accessibility audit** of the panel, list modes, banners, Settings, welcome and About: VoiceOver
  labels and announcements, Reduce Motion, Reduce Transparency, Increase Contrast, Differentiate
  Without Colour, the text-size setting and full keyboard access. Code-level fixes here; the
  VoiceOver walkthrough and Accessibility Inspector run are manual QA items in the PR body.
- **4.4 Landing page** `docs/index.html` (structure modelled on AudioPin: en/pl, download, Gatekeeper
  "Open Anyway", permissions, features, FAQ) with no committed images (the panel is an HTML mock-up
  with fixture data); `.github/workflows/pages.yml` builds on PRs and deploys from `main`. README with
  DMG install, Gatekeeper, permissions and features.
- **4.5 Budgets** measured with the existing signposts and benchmarks, recorded in `docs/perf.md`.
- QA flags for the new windows in `docs/qa.md`; `AGENTS.md`, `BACKWARD_COMPATIBILITY.md`; `en` + `pl`.

## Non-goals

- New features (spec: "Bez nowych funkcji").
- Changing the repository's Pages settings, tagging `v1.0.0` or publishing a Release (owner steps).
- Fixing the racy `AppsPluginLifecycleTests.activationScansTheConfiguredRootAndCachesTheList` (owner
  decides on a follow-up).
- Uploading screenshots to GitHub (blocked by the permission system; evidence stays local).
- The `om-auto-review-pr` loop (a separate reviewer runs it).

## Risks

- A Keychain row in the Permissions pane would need the shell to read the clipboard plugin's key
  state; Keychain is not a TCC permission and has no System Settings pane. The pane points to the
  plugin's own pane instead (spec deviation, recorded in the PR).
- Budgets that need the owner's real home folder (first scan of `~`, memory with ~500 k files) cannot
  be measured by an agent; they stay manual items with the procedure in `docs/perf.md`.
- Memory right after the first scan of ~510 k entries is 199–222 MB (budget < 150 MB at rest); after a
  restart it is 85 MB. The excess is freed memory the allocator keeps (`docs/perf.md`); left as a
  follow-up.
- 7.3 stays open: screenshots are captured locally only, because uploading images to GitHub is
  blocked in this run.

## Implementation Plan

### Phase 1: Settings panes (spec 4.1)

1.1 Permissions pane. Test: the rows follow the enabled plugins' permissions, states and deep links.
1.2 Advanced pane with Reset Ranking. Test: reset empties `ranking.sqlite`; the pane's action calls it.

### Phase 2: Welcome screen (spec 4.2)

2.1 Welcome model and window replacing the step-by-step onboarding, QA flags. Test: step order,
skip/continue/back, completed steps persisted and not shown again.

### Phase 3: About window

3.1 About window with the third-party notices, QA flag. Test: notices load from the bundle, menu item.

### Phase 4: Accessibility audit (spec 4.3)

4.1 Panel, list modes and banners. Test: unit tests for announcements and contrast/motion settings.
4.2 Settings, welcome and About: labels, keyboard access, text size; audit record. Test: unit tests.

### Phase 5: Landing page and README (spec 4.4)

5.1 `docs/index.html` and `pages.yml`. Test: the Pages build job is green.
5.2 README: install from the DMG, Gatekeeper, permissions, features, building from source.

### Phase 6: Budgets (spec 4.5)

6.1 Measure the budgets and record them in `docs/perf.md`.

### Phase 7: Docs and verification

7.1 `docs/qa.md`, `AGENTS.md`, `BACKWARD_COMPATIBILITY.md`, Polish strings.
7.2 Full validation gate.
7.3 UI evidence (window-only screenshots with fixture data, light/dark, en/pl) attached to the PR.
